# Mobirise 原型審查（2026-04-26）

來源：
- https://ai-builder.mobirise.com/pages/YPjg6CvVrMVJJDd4lokdS?seed=eqp1lxjjip

## 結論（先講重點）

- **不建議直接拿這版去送審**。
- 這版比較像「行銷官網 landing page」，不是「Mini App 內可操作產品流程」。
- 可保留視覺語言，但必須先收斂成 5–6 個核心產品畫面與真實交易流程。

## 主要風險

1. **頁面資訊過載，像宣傳站而非 App flow**
   - 大量重複區塊（特色、評價、價格、文章）會稀釋核心任務：登入、抽卡、結果、付費、歷史。
2. **交易模型混亂**
   - 同時出現多個價格與方案（$5/$10/$20、不同方案文案），易被視為不清楚或誘導。
3. **真實產品狀態不足**
   - 看不出完整的 Loading / Empty / Error / Success 四態，以及支付失敗與重試路徑。
4. **政策與風險聲明不夠前置**
   - 雖有提到隱私，但不夠具體；未明確強調「非投資／非醫療建議」。

## 可以保留的優點

- 視覺基調（米金色、卡片語彙）方向正確。
- 已有「抽卡、結果、付款、設定」導航概念，可轉成真實 app IA。
- 有 FAQ 與歷史概念，可轉為產品內說明而非長頁堆疊。

## 建議 48 小時內修正項目（提審最小版）

1. 只保留 6 個畫面：
   - Home（未抽）
   - Draw Result（已抽）
   - Payment Sheet（單一 SKU）
   - Deep Reading（已購買）
   - History（7 天）
   - Settings（Terms/Privacy/Contact）
2. 價格只保留一個 MVP 方案：`daily_deep_read`（單次解鎖）。
3. 補齊四態畫面與錯誤文案：
   - 網路逾時
   - 重複抽卡
   - 支付失敗
   - webhook 未確認
4. 在付款前與設定頁加上：
   - 用途說明
   - 退款/取消規則
   - 非投資、非醫療聲明
5. 移除與 MVP 無關的長文與大量 testimonial 模組。

## 審核前自檢（可直接貼給團隊）

- [ ] 首屏 10 秒內完成「登入→抽卡」
- [ ] 每日只可抽一次（有防重）
- [ ] 近 7 天歷史可回看
- [ ] 單一 SKU 可完成付款並回寫 entitlement
- [ ] 條款 / 隱私 / 客服入口明確
- [ ] 四態（Loading/Empty/Error/Success）完整
- [ ] 風險聲明清楚（非投資/非醫療）
